# 설계: branch_paths 보정 + 언리얼 11-18 계약 동기화 (2026-11-19)

## 배경 / 왜 지금

- 3차 중간 산출물(구현 보고서·테스트 결과서·발표자료) 마감이 오늘(11-19). 녹화 발표 없음.
- 언리얼(Choibw/LLMDrivenPlayablePCG `80a1ee1`, 11-18)이 선택 필드 `branch_paths`(분기/지름길)와 `danger` 구역, `path_width` 실제 적용을 추가했다.
- 백엔드 validator는 `branch_paths`를 모른다 → 서버를 거치면 다중 경로가 항상 사라진다.
- 언리얼은 `branch_paths`가 있으면 원소 하나라도 잘못됐을 때(객체 아님, 점 < 2, 좌표 비정상/범위 밖, path_width 비유한) **존 전체를 실패**시킨다(`PCGZoneController.cpp` ApplyZoneJsonString). 마지막 보정 지점인 백엔드가 막아야 한다.
- LLM 레포(kjs1214, 마지막 9-28)는 변화 없음: HTTP API 없음, 스키마에 `danger`/`branch_paths` 없음.

## 범위 결정 (사용자)

- 대화 → 분기/danger "생성"은 LLM 파트 몫. 규칙 해석기·vLLM 프롬프트/스키마는 건드리지 않는다.
- 백엔드는 들어온 `branch_paths`를 언리얼이 반드시 읽을 수 있게 보정하거나 버린다.

## 목표

1. `branch_paths` 입력을 보정해 출력. 출력에 포함된 branch는 언리얼 파서를 항상 통과.
2. 언리얼 목 파서를 11-18 코드 기준으로 갱신(branch 규칙 포함).
3. 불변식·fuzz·결과서·README 갱신. 기존 계약/불변식/멱등성 유지.

## 비목표 / 안티골

- 비목표: 분기 자동 생성, areas를 분기 위에 배치, 분기-메인 교차 판정, 테마 에셋.
- 안티골: branch 하나 때문에 언리얼이 존 전체를 거부. 멱등성 깨짐. branch 없는 기존 응답이 바뀜(키 추가 포함).

## 설계

- `normalizeInput`: `branch_paths`가 배열이면 원소별 `{type, width, points}`로, 아니면 null(존재하는데 배열 아님 → 리포트 후 무시).
- 상한: 분기 최대 2개(`CONFIG.branch.max`), 분기당 점 2~12.
- 원소 보정(`fixBranch`):
  - path_type: `branch`/`shortcut`(대소문자 무시), 그 외 `branch`.
  - path_width: 숫자면 [100,1500] 클램프, 없으면 기본 400.
  - 점: 숫자 아닌 점 제거 → 가장자리 여백 → 근접점 병합 → 2-opt → 급회전 완화/제거 (메인과 같은 헬퍼 재사용, spawn-goal 거리 규칙은 적용 안 함).
  - 결합: 첫 점을 메인 경로 최근접점으로 스냅. `shortcut`은 끝점도 스냅하고, 끝점 진행도가 시작점보다 앞이면 점 순서를 뒤집는다.
  - 버림 조건: 객체 아님, 정리 후 점 < 2, 길이 < 0.1, 자기교차 잔존, shortcut 양 끝 진행도 차 < 0.06. 버린 이유는 리포트에 남김.
- 출력: 유효 분기가 1개 이상일 때만 최상위 `branch_paths` 키 추가(없으면 키 자체 없음 → 기존 응답과 바이트 동일).
- 멱등: 스냅된 끝점이 이미 경로 위(거리 ≤ TOL)면 그대로 둔다. fuzz로 확인.

## Approaches

1. **validator 안에서 보정(채택)**: 메인 경로 기하 헬퍼를 그대로 재사용, 리포트·멱등성·fuzz 체계에 자연스럽게 들어감.
2. 그대로 통과(passthrough) + 형식 검사만: 구현은 짧지만 메인 경로와 동떨어진 분기, 교차 분기를 그대로 보냄.
3. 분기 전부 제거: 지금 상태. 언리얼 신기능을 막음.
