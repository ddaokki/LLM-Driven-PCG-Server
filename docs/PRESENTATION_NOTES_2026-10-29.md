# 3차 중간발표 백엔드 발표 노트 (2026-10-29)

발표 포인트는 세 문장이다.
1. **백엔드가 이제 "데이터 포장기"가 아니라 "레이아웃 보정 엔진"이다.** LLM이 무엇을 내든 언리얼이 그대로 읽고 플레이 가능한 존이 나온다 — 무작위 망가진 입력 2,000건에서 실패 0.
2. **대화가 실제로 존을 바꾼다.** LLM 서버가 아직 없어도 규칙 기반 해석기로 전체 파이프라인(dialogue → 후보 → 보정 → 언리얼)이 돈다. LLM이 붙으면 `.env` 한 줄.
3. **전부 테스트와 결과서로 증명된다.** 명세서 BE-T01~T12를 포함해 98건 자동화, `npm run test:report` 한 번에 결과서(md/docx).

## 2. 시연 (3분)

사전: `npm start` (Redis/LLM 없어도 됨). 터미널 하나 더 열어 `npm run demo`.

### 시연 A — 대화가 존을 바꾼다 (`npm run demo` ①②③)
- ① "어둡고 나무가 빽빽한 숲, 구불구불한 길, 중간에 전투 3번" → forest, tree 0.8, 경로 8점, combat 3개, 보정 0건
- ② "바위투성이 사막, 곧고 넓은 길, 전투 없이 탐험" → desert, rock 0.9, 경로 5점 폭 966, combat 0개
- ③ "눈 덮인 설원에서 보스급으로 격렬한 큰 전투 두 번" → snow, combat 2개, r≈0.12, detail≈0.8
- 말할 것: intent 줄(테마/전투수/길 모양/강도/크기)과 seed. 같은 대화 = 같은 seed = 같은 존(재현성), `seed` 필드로 변형.

### 시연 B — 깨진 LLM 출력 복구 (`npm run demo` ④)
입력: 8자로 꼬인 경로, 모르는 테마 "lava", 밀도 2.5, 구역 3개가 한 점에 겹침, spawn 없음, boss_zone 타입.
출력: 교차 풀린 경로, forest, spawn 추가, goal 경로 끝점으로 스냅, 두 combat이 경로 따라 분리, 난이도 오름차순, **언리얼 파서 OK**.
말할 것: 리포트의 "위반 3건 → 보정 12건 → 품질점수 0.34". 품질 점수는 LLM 출력이 얼마나 손 안 대고 쓸 수 있었는지의 지표 → 나중에 프롬프트/파인튜닝 효과 측정에 쓴다.

### 시연 C — 언리얼 (병욱 님과 합이 맞으면)
언리얼 `RequestZoneDataFromBackend` → Output Log `Backend Response Code: 200` → 뷰포트에 combat 3개 생성 → 서버 콘솔 한 줄 로그.

## 3. 질문 대비

- **Q. LLM 없이 규칙으로 하면 LLM 프로젝트가 아니지 않나?**
  해석기는 LLM 자리의 *폴백*이다. 인터페이스(후보 Zone JSON, 스키마)는 LLM 레포 `app.py`와 동일하게 맞춰 놨고, vLLM 클라이언트는 타임아웃/실패/깨진 JSON까지 테스트돼 있다(LLM-01~09). GPU 서버가 열리면 `LLM_API_URL`만 넣는다. 그리고 LLM이 붙어도 validator는 그대로 필요하다 — LLM 파트 자체 테스트에서도 전투 겹침 등 "복구 안 되는 드문 경우"가 남는다고 보고했다.
- **Q. 보정이 LLM 의도를 지워버리는 것 아닌가?**
  규칙을 어긴 경우에만, 어긴 만큼만 움직인다(lazy). 비율(밀도), 순서(진행도), 강도 분포(값 집합), 중심 위치를 반지름보다 우선 보존한다. 무엇을 왜 바꿨는지 리포트로 남겨 LLM 파트가 프롬프트를 고칠 근거가 된다.
- **Q. 멱등성이 왜 중요한가?**
  보정 결과를 언리얼이 캐시했다가 다시 보내거나, 세션에 저장했다가 재사용해도 값이 흔들리지 않는다. 또 "출력이 모든 규칙을 만족한다"의 가장 강한 검증이다. tanh 소프트 클램프는 이것과 수학적으로 양립 불가라 제거했다.
- **Q. 1차 때의 소프트 클램프는 어디 갔나?**
  테마별 하드 클램프에 항상 지배되어 출력에 영향이 없었고(증명 가능: tanh(v) < 0.8 ⇔ v < 1.1, 그 위는 0.8로 잘림), 멱등성을 깬다. 대체 가치는 "보정 리포트".
- **Q. 언리얼 쪽 Area 액터 개수 제약은?**
  10/27 커밋에서 자동 생성으로 바뀌어 해소. 대신 "모든 combat 클리어 → goal" 규칙이 생겨 combat 개수 일치와 난이도 순서가 플레이 흐름에 직접 연결된다.
